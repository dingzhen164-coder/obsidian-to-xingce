# book-to-ankicard：书 → Anki 卡片

把书拆成“**一张卡一个知识点**”的**问答卡**（不做填空卡），输出 UTF-8 的 `.tsv`，Anki 桌面版“文件 → 导入”即可。

**硬规则**
- **先预览，后生成。** Step 4 给出每章样卡并停下，用户确认前不得整本生成。
- **只做问答卡**（Anki 的 Basic 笔记类型）。不做填空、不做反向卡，除非用户明确要求。
- **每张卡必须带 `evidence`**（书中原文片段），生成后用脚本核对；找不到的卡要回原文复查，不能留。
- 默认**中文**输出；书是别的语言时，问题答案仍用中文，术语保留原文。
- 每章卡片数由**内容密度**决定，不设固定数量。

文件说明：`scripts/extract.py`（提取文本）、`scripts/build_tsv.py`（校验并导出）、`references/card-design.md`（**拆卡规范，生成前必读**）。

---

## Step 0 — 参数

- 书文件路径（必填）。没给就停下来要。
- 牌组名：没给就用书名；用 `::` 可做子牌组，如 `行测::定义判断`。
- 输出目录默认 `./anki-<书名slug>/`，其中：`cards/chNN.jsonl`（每章一个文件，可断点续做）、`<书名slug>.tsv`、`preview.md`。

## Step 1 — 提取文本

```bash
python3 -I "<本 skill 目录>/scripts/extract.py" "<书文件>" --out "<工作目录>"
```

产出 `full_text.txt` 与 `metadata.json`（字数、页数、章节候选）。**以 `Workdir ->` 打印的路径为准**，不要假设固定位置。
- PDF 靠 `pdftotext`；扫描版 PDF（提取出来几乎没字）无法处理，告诉用户需要先 OCR。
- 图片、图表、思维导图不会被读取——在最终报告里说明。

## Step 2 — 确认书的类型

读 `references/card-design.md`，然后判断并**向用户确认**：

| 类型 | 特征 | 拆卡重点 |
|---|---|---|
| **方法论型** | 知识点少、例题多、讲思维体系（如行测讲义） | 体系卡、方法卡、**触发卡**、易错卡；例题只提炼迁移卡 |
| **记忆型** | 知识点密、例题少、重记忆（如法考教材） | 逐点覆盖；数字/期限/要件逐字准确；列举拆分 |
| **混合** | 两者兼有 | 按章/按节分别套用 |

能从书里判断就给出建议（“看起来是方法论型，因为……”），让用户点头或纠正，**不要空手问**。

## Step 3 — 结构与目录

1. 读全书开头约 6000 字找**目录**，目录是章节划分的依据。
2. 对照 `extract.py` 打印的章节候选（启发式，可能把“一、二、”小节当成章，也可能漏掉装饰过的章标题）。以目录为准，用 `grep -n` 在 `full_text.txt` 里定位每章起止行。
3. 大书（> 5 万字）不要整本一次读入：按章用 `sed -n '起,止p' full_text.txt` 取片段，再处理。

## Step 4 — 预览（必须）

按 `references/card-design.md` 第四节的格式，对每章给出：知识点个数、预计卡数及构成、3–5 张**样卡**。样卡要真实、可直接入库。写入 `preview.md` 并在对话里展示。

随后给出全书预计总卡数，列出需要用户决定的点，然后**停下，等待确认**。用户提出修改（风格、粒度、是否做某类卡），先调整样卡再确认。

## Step 5 — 逐章生成

确认后，按章处理（章与章互相独立，规则必须一致；章数多时可并行，但每个并行单元都要先读 `references/card-design.md`）。

每章：
1. 取该章原文片段，通读后**先列知识点清单**，再逐点拆卡。
2. 写入 `cards/chNN.jsonl`，一行一卡：

```json
{"front":"问题","back":"答案","tags":["第3章","主题词"],"source":"第3章 二、小节名","evidence":"书中原文8到40字","kind":"method"}
```

- `kind` 取：`concept` `method` `trigger` `rule` `pitfall` `compare` `number` `example` `system`。
- `evidence` 必须是**从 `full_text.txt` 里复制的原文**，不要改写、不要概括。
- 答案里可用 `\n` 换行、`**加粗**`；不要写 HTML。

## Step 6 — 校验并导出

```bash
python3 -I "<本 skill 目录>/scripts/build_tsv.py" "<输出目录>/cards" \
    --deck "<牌组名>" --out "<输出目录>/<slug>.tsv" --source "<工作目录>/full_text.txt"
```

逐条处理警告：
- **evidence 找不到** → 回原文核对。确有此内容就改成原文写法；原文没有就**删卡**。
- **问题重复 / 依赖上下文 / 答案过长** → 合并、改写或拆分。
- 处理完重跑，直到没有警告（或剩下的是你明确接受的）。

## Step 7 — 抽检与交付

1. 随机抽 10–15 张，对照原文复核：是否单一知识点、是否脱离书本能看懂、数字/期限是否一字不差。
2. 汇报：总张数、各类型分布、每章张数、被删/被改的卡数、未能读取的内容（图片等）。
3. 告诉用户如何导入：

> Anki 桌面版：**文件 → 导入** → 选 `.tsv` → 确认“允许 HTML”已勾选、笔记类型为 Basic、牌组名正确 → 导入。
> 手机端（AnkiDroid / AnkiMobile）请先在电脑导入，再同步。
> 文件头已声明分隔符、HTML、笔记类型、牌组和标签列，Anki 2.1.54 及以上会自动识别。

## 范围与限制

- 只处理文字内容；图表、图片、公式图不会成卡。
- 卡片质量取决于对书的理解：**记忆型书的数字、条文、期限**务必让用户在预览或抽检环节重点复核。
- 本 skill 只生成文件，不替用户调用 Anki。
