# 卡片设计规范

> 生成卡片前必读。第一节是所有书通用的规则；第二、三节是两类书各自的拆卡策略；第四节是预览格式。

## 一、通用规则（所有书）

1. **一张卡只对应一个“记忆单元”。** 记忆型书里，单元是**一个知识点**（答错时你能说清“是哪一个点没记住”；答案里出现“以及/同时/另外”往往意味着该拆）。方法论型书里，单元是**体系中的一个节点**（一个方法/一类关键信息），一张卡可以包含要点＋例题（见第二节）。**先判断书的类型，再决定单元大小，不要把方法论型的书拆成一句话一张。**
2. **问题必须脱离书本也能看懂。** 写全主语和范围，禁止“本章/上文/该方法/这一讲/如上”。
   - ✗ 该方法的第二步是什么？
   - ✓ 定义判断的“解题三步”中，第二步做什么？
3. **答案要短、可对照。** 记忆型：理想 ≤ 80 字，上限 400 字。方法论型的体系节点卡可以到 800–1500 字，但必须**分层排版**（小标题、列表、表格），不能是一大段文字。
4. **问法要明确是“在检索什么”。** 用“是什么 / 怎么做 / 什么时候用 / 区别是 / 共几项分别是 / 期限是多少”开头或结尾，不要问“谈谈……”。
5. **改写，不抄原文。** 把原文的陈述改成可检索的问答；但**数字、期限、主体、条件、例外一律照原文，不得“优化”**。
6. **不造书里没有的内容。** 每张卡必须有 `evidence`（书里的一小段原文，8–40 字，复制原文，不要改写）。`build_tsv.py --source` 会核对它是否真在书里。自己的补充、常识、外部知识，不写进卡片。
7. **不凑数。** 重复表述同一点的卡、纯修辞/鼓励/过渡性文字，一律不做卡。
8. **标签**：`第N章` + 主题词（如 `拆词法`）。不含空格；层级用 `::`。
9. **出处（source）**：`第N章 小节名`；有页码/条文号时一并写，如 `第3章 二、…（P52）`。

### 反面样例（主要针对记忆型）

| 问题 | 为什么不行 | 怎么改 |
|---|---|---|
| Q：简述本章内容 | 太大、没有检索点 | 删除，拆成具体知识点 |
| Q：解题三步分别是什么？A：（三条各一长段） | 一张卡塞三个知识点，答案过长 | 一张“总览”只答每步一句；每步各自展开一张 |
| Q：政府与企业有何不同？A：政府不营利 | 只答一半 | A：政府不以营利为目的；企业往往以营利为目的 |
| Q：该方法什么时候用？ | 依赖上下文 | 写出方法名和适用对象 |

## 二、方法论型（例：行测讲义）

**特点**：真正的知识点很少，篇幅主要是例题和铺垫；价值在于**形成体系、能在题干里认出该用哪个方法**。所以**卡片少而精，按体系节点拆，不按句子拆**。（用户实测反馈：同一本书，按句子拆出 170 多张，按体系拆只需要几十张；多出来的基本都是噪音。）

### 步骤

1. **先通读目录，判断每一节是“体系内容”还是“背景内容”。**
   - 背景内容**不做卡**：什么是XX、考情与难度分布、痛点与心态、学习方法、开场/回顾/复盘表、小结里的重复、“写在最后”、鼓励性文字。
   - 拿不准的（例如“解题三步”这类流程性内容）**照做，但打上 `可删` 标签**，让用户自己决定留不留。
2. **找“跨章同名/同类的大标题”——它们就是体系的骨架。**
   - 例：行测讲义里“关键信息之一……之六”“需要积累的关键信息”分散在第1、2章，它们**同属一个体系“关键信息”**，要合并成一组卡，而不是按章切开。
   - 同一个概念在多章出现（先讲方法、后面章节反复运用），**汇总成一张卡**，`evidence` 给多段，`source` 写清所在各章。
3. **对每个体系，做“1 张体系总览卡 ＋ 每个子项 1 张卡”。**
   - **体系总览卡**：把这个体系下的**所有子项**列出来，每项**一两句话**说清“是什么、怎么用”，再补优先级/取舍原则。问法：“XX 里有哪几类？各自怎么用？”
   - **子项卡**：一项一张。结构固定为 **是什么 → 怎么用/常考点 → 例题**。
   - 总原则、取舍、优先级之类**跨子项的规则**，单独一张卡。
4. **每张卡里放 1–3 道精简例题。**
   - 例题用引用块（`> `），写成：**（年份地区 定义名）一句话定义要点 → 关键判断步骤 → 答案**。
   - 不要把整道题（含四个选项）搬进来；只保留“题干特征 → 抓哪个信息 → 为什么排除/选中”。
   - 例题要**选对本卡主题有代表性的**，宁可少，别硬凑。同一道例题可以服务多张卡，但每张卡里只讲与本卡相关的那一面。
5. **全书结束后，检查体系是否完整**：每个体系有总览卡；子项卡数量与总览卡里列的子项一一对应。

### 数量参考

不设固定数。一个体系 ＝ 1 张总览卡 ＋ N 张子项卡（N 就是子项个数）＋ 0–2 张跨子项规则卡。**例**：《定义判断》第1、2章合计只有“关键信息”一个体系：总览 1 ＋ 6 个子项 ＋ 取舍 1 ＝ **8 张**，外加 1 张可删的“解题三步”。

### 排版

方法论型的卡内容较多，**必须排版**（脚本支持的标记见 `build_tsv.py` 开头）：

- `# 小标题` 分层（是什么 / 怎么用 / 常考点 / 例题）
- 要点用 `- ` 列表；步骤用 `1. ` 有序列表
- 对照类内容（引导词、拆词表、积累清单）用 `| a | b |` **表格**
- 关键词用 `**加粗**`，最关键的结论用 `==红色加粗==`（整张卡里不超过 3–4 处）
- 例题用 `> ` 引用块，与正文区分
- 段落之间留空行

## 三、记忆型（例：法考教材）

**特点**：知识点极多、例题很少，重点是**逐点记牢，准确**。宁可卡多，也不要漏掉能考的点；但**每张仍只问一个点**。

**常见卡型**：

| 类型 | 问法 | 注意 |
|---|---|---|
| 定义/概念 | X 是什么？ | 答案保留定义里的关键限定词 |
| 构成要件 / 条件 | X 的构成要件有几个？分别是什么？ | 见下方“列举型” |
| 数字类 | 期限 / 数额 / 比例是多少？ | **逐字照抄**，带条件（“自……起算”）。每个数字一张卡 |
| 区别辨析 | A 与 B 的区别是什么？ | 一个区别点一张卡，不要一张卡列五条区别 |
| 例外 / 但书 | X 的例外情形有哪些？ | 单独成卡，常考 |
| 后果 / 效力 | X 的法律后果是什么？ | 主体、后果分清 |
| 出处 | 哪条规定了 X？ | 仅在书中明确给出条文号时才做 |
| 案例判断 | （简化案情）该行为是否构成 X？ | 只为书中确有的少数例题做卡，案情压到最少 |

**列举型的拆法**：
- ≤ 4 项：一张卡，问中写明“共几项”，答案按序号。
- 5–8 项：一张**总览卡**（只答数量和各项名称）＋ 对易混/重点项各做一张**展开卡**。
- > 8 项：按类别拆成若干组，每组一张，再加一张总览。

**精确性红线**：数字、期限、“应当/可以/不得”、主体、前置条件、例外——**不得改写、不得合并、不得补全**。拿不准就保留原文措辞，并在预览中标出让用户确认。

**密度参考**：一个段落通常 1–3 个知识点；一页教材 5–15 张卡是常见范围。仍以“该点是否可单独考到”为准。

## 四、预览格式（Step 4 必须先给用户看，分两步）

**第一步：结构大纲（先确认体系，再谈样卡）**

```
### 体系 / 卡片清单
- 【体系】关键信息（第1–2章）：总览卡 + 子项卡 6 张 + 取舍卡 1 张
    1. 总览：关键信息有哪几类
    2. 定义词（拆词法）        ← 第1章五
    …
- 【可删】解题三步               ← 第1章四（流程性，拿不准）

### 不做卡的部分（逐条说明原因）
- 第1章 一、二、三：背景（什么是定义判断、考情、痛点）
- …
```

用户确认或修改大纲后，再做第二步。

**第二步：样卡**——从大纲里选 **2–3 张**完整样卡（含排版、例题），用 `build_tsv.py` 导出并渲染给用户看（排版是否合意也要一并确认）。

最后给出全书预计总卡数，列出需要用户决定的点，然后**停下，等用户确认**，再开始全书生成。

记忆型书的预览沿用“每章 3–5 张样卡 + 知识点数 + 预计卡数”的格式；估算时先数知识点个数，再乘每点卡数，不要用字数直接换算。
