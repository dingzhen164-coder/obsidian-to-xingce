# political-theory-reasoning

## 适用范围

本 Skill 用于政治理论类题目的最终分析。

它不自行定义用户的“三层级”方法，而是每次实际读取用户指定的方法文件后再工作。

## 强制读取方法文件

每次处理本 Project 的核心题目时，必须先实际读取：

Obsidian 库里的 `行测/政治理论/00-三层级做题总框架.md`

（本机完整路径：`/Users/gasby/Desktop/行测obsidian/行测/政治理论/00-三层级做题总框架.md`。换电脑或换系统时，按库内相对路径找。）

必须优先遵守其中原有的：
- 层级划分
- 步骤
- 顺序
- 术语
- 分类
- 判断标准
- 输出结构

不得仅凭文件名推测“三层级”的具体内容。
不得用模型自己的政治理论通用答题框架替代。

如果读取失败，必须明确说明：

> 无法读取“00-三层级做题总框架.md”，因此无法保证按照用户指定框架完成分析。

此时不得静默改用模型自带方法。

## 可调用的知识库 Skill

### 治理母逻辑
`governance-logic-kb-search`

固定知识库：
`01-治理母逻辑`

### 政策敏感度树
`policy-sensitivity-kb-search`

固定知识库：
`02-政策敏感度树`

根据题目需要调用其中一个或两个。
不得为了“看起来更充分”而机械同时调用两个知识库。

## 分析原则

最终结论必须能够由以下材料推出：
- 题干；
- 实际读取的 `00-三层级做题总框架.md`；
- 实际检索到的 `01-治理母逻辑` 知识点（如有）；
- 实际检索到的 `02-政策敏感度树` 知识点（如有）。

不得：
- 先猜答案，再反向寻找支持；
- 用模型记忆冒充知识库结果；
- 把一个知识库的内容说成来自另一个知识库；
- 编造本地知识库没有明确支持的规则；
- 自行补写“三层级”方法中不存在的步骤；
- 因为某个选项更熟悉就绕开用户指定框架。

## 标准执行顺序

1. 判断题目是否属于政治理论题；
2. 实际读取 `00-三层级做题总框架.md`；
3. 严格按该文件的原有层级和步骤识别题目；
4. 判断需要治理母逻辑、政策敏感度树，或两者都需要；
5. 对每个需要的知识库提炼 2～4 个核心检索概念；
6. 调用对应检索 Skill；
7. 首轮每个知识库最多获取 3 条知识；
8. 材料足够则停止；
9. 确实不足时，对对应知识库最多补充检索 1 次；
10. 严格按照用户方法文件完成分析；
11. 给出答案、依据、易错点与知识来源。

## 来源纪律

如果某个结论只能由题干或方法框架推出，而不是来自知识库，要明确区分。

如果知识库没有检索到明确依据，应写：

> 知识库未检索到明确依据。

不得把模型自己的常识、政治观点或外部信息伪装成本地知识库内容。

## 被 xingce-jiexi-all 调度时

被总调度 skill 派来处理某一季的政治理论板块时，按下面流程**直接把解析写进板块 md 文件**，不在对话里输出长篇解析。

`<jiexi>` 指 `xingce-jiexi-all/scripts/jiexi.py`（和本 skill 在同一个 skills 目录下）。路径一律加英文双引号；Windows 上 `python` 不可用就换 `py`。

### 流程

1. **开工前准备（整个板块只做一次）**：读取 `00-三层级做题总框架.md` **一次**，整个板块的所有批次都按这一次读到的内容做，不要每题重读。读取失败就停下，报告“无法读取框架文件”，不要改用自带方法。
2. 取一批题：`python "<jiexi>" next "<第N季目录>" 政治理论 [--mode 错题|全部]`
   输出里有板块文件路径、本批题号、题干、选项、正确答案、我的答案，以及截图完整路径。有 `[截图]` 的必须打开截图看。
3. 按本 skill 的方法解这一批题，遵守：
   - **以正确答案为锚**：推导必须落到给出的正确答案；推不出来就写一行 `⚠ 待核对：<卡在哪一步>`，不要硬编；
   - 我答错时，点出我选的选项错在哪。
4. 按下面「解析写法」把这批解析写进临时文件（如 `<第N季目录>/.jiexi-tmp.md`），每题以 `=== 题号` 开头，然后写入：
   `python "<jiexi>" write "<第N季目录>" 政治理论 "<临时文件>"`
   （脚本会给每行加 `> `，只写空的复盘栏，不会覆盖已有笔记。）
5. 重复 2–4，直到 `next` 显示“没有待解析的题”。
6. 检查格式：`python "<jiexi>" check "<第N季目录>" 政治理论`，有 ❌ 就按提示修好。
7. 回报一句话：写入了几题、哪些题标了待核对。

### 省 token 规则

- 框架文件整个板块只读一次（见流程第 1 步）。
- 知识库检索仍按「标准执行顺序」第 5–9 步：每题每库首轮最多 3 条、不足才补 1 次；**只按需调用**，不为了“看起来充分”两个库都查。
- 同一批里几道题考同一个知识点时，检索一次共用，在各题来源里都写上。

### 解析写法

按 `00-三层级做题总框架.md` 里的输出结构写；框架文件没规定的部分用：
```
=== 3
【答案】A
【层级】……（按框架文件的层级和术语）
【分析】……
【易错】我选 C 错在……（答对可省略）
【来源】治理母逻辑·<知识点>；政策敏感度树·<知识点>（没检索到就写“知识库未检索到明确依据”）
```
被调度时，「默认输出尾注」压缩成上面一行【来源】，不再列方法模板和 skill 名。

### 不能运行 python 时

可以直接编辑板块 md，但必须遵守：只改 `> [!note] 复盘` 下面、该题 `---` 之前的内容；每一行都以 `> ` 开头，空行写成 `>`；复盘栏已有内容的题不要动；不改题干、选项、答案行、frontmatter 和速览表。
